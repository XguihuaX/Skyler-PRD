## 1. 当前结论

可以围绕已经完成绑定的模型批量制作动作与表情。建模产物必须包含可驱动结构：3D 的骨骼、蒙皮和面部形变，或 Live2D 的网格、变形器、关键形与参数。只有外观网格或分层 PSD 时仍需绑定。单图中遮挡的形状与纹理由生成或补画提供，不能保证恢复原作者的全部图层/隐藏结构。

- 3D：网格/纹理 → 骨骼与蒙皮 → 面部形变/控制 → 动画片段与表情预设。
- Live2D：分层与补画 → 网格/变形器/关键形与参数 → 动作曲线与表情预设。
- 可读取的是实际创建并导出的控制结构；不存在无条件自动获得“所有人体关节点/所有图层”的保证。
- 对同一模型，参数组合和时间曲线可以批量生成；跨模型复用要统一控制含义、名称/映射、范围和初始姿态，并预览校准。

## 3. 为何能批量做预设

动作可表示为控制值随时间变化，表情可表示为一组控制值及混合方式。自拟示例：

- 点头：头部俯仰随时间变化，结束回中立；改变幅度、速度、次数可生成多个版本。
- 微笑：笑眼、嘴角、眉毛的组合；只有模型已有相应绑定时才有效。
- 鼓励：微笑加点头，可在模型具备手臂控制时叠加挥手。
- 羞涩：目光偏移、低头及模型已有的脸红素材/参数；没做脸红素材时，仅写一个参数名不会产生它。

[Live2D 参数说明](https://docs.live2d.com/en/cubism-editor-manual/parameter/)明确参数关键形之间插值，组合参数形成动作；跨模型使用相同参数 ID 有助于复用动作。[标准参数](https://docs.live2d.com/en/cubism-editor-manual/standard-parameter-list/)提供推荐命名，但仍需实际绑定及范围匹配。[表情导出](https://docs.live2d.com/en/cubism-editor-manual/setting-and-exporting-facial-expressions/)支持批量导出 exp3.json；[运行数据](https://docs.live2d.com/en/cubism-editor-manual/export-moc3-motion3-files/)包括 moc3、model3.json、motion3.json 等。

大量参数组合不等于大量自然的表演。初次制作可先批量生成预览，再挑选调校；眼睛、嘴型、动作与物理同时驱动同一参数时要处理叠加和优先级。

## 4. 交付与 Momo 接入建议，待用户确认

1. 保存可编辑源工程：Live2D 的分层 PSD、cmo3/工具工程；3D 的源工程、纹理、骨骼/蒙皮和面部形变。
2. 导出可运行资产和已支持动作/表情清单。moc3 运行包不能等同于完整 PSD/cmo3；3D 文件扩展名本身也不证明骨骼或表情齐全。
3. 每个角色建立可用控制清单及必要映射；缺失的动作/表情不作为可用能力展示。
4. 建立可复用动作/表情库，播放时指定预设与强度/时长等实际支持选项。应用运行阶段无需每次从图片重新建模。
5. 首个验证使用一张用户选定角色图，完成分层/绑定后检验点头、眨眼、口型、一个组合表情和动作极值；再在 Momo 目标播放器验证，不因生成文件存在就视为完成。

制作端的资源消耗与日常播放分开评估。当前仅形成研究结论与需求建议，不实施编辑器、不强制用户在 Momo 管理全部原始参数。

## 6. LumenAct：自然语言驱动表情（2026-11-18 续查）

已定位 [官方源码](https://github.com/AaBb-coder/LumenAct) 与 [公开模型资源](https://huggingface.co/AaBbcoder/LumenAct)，核对源码版本 `ad933bce20f0567e4ab4d97be306e39997310a21` 的 README、docs/API.md、docs/FORMAT.md、docs/ADAPTING_YOUR_MODEL.md、docs/BOUNDARIES.md 及 server.py、preview/chat-director.js。以下为文档/源码核对，未安装或测量运行效果。

### 6.1 实际链路与可复用部分

- 中文表情意图及可选台词 → RBT3-Lumen-38M-v6 CPU ONNX 输出情绪类别、上下文与语音风格 → 选择已有曲线 → 播放器采样、插值，写入可匹配的面部形态键。公开版没有第二个表情生成 ONNX。
- 公开素材包含 97 段表演及 166 维原始控制曲线。166 包含肌肉/骨骼等列，不等于 166 个面部形态键；FORMAT 另列 112 个可调脸部键，README 中 Blender 参考脸含 118 个键，三者口径不同。
- 网页包含基础视线跟随、头部微动、0.4 秒普通淡入淡出、结束回自然循环。复杂动作图、惯性过渡与完整口型系统未公开。
- `POST /api/semantic` 接收 `intent`、`text`，返回 `expression`、`confidence`、`context_id`、`context_name`、`speech_style`、`top_labels`、`elapsed_ms`、模型名。耗时仅涵盖语义选择，不是完整对话延迟。实际内存/延迟尚未测量。
- 示例 `(微笑)早上好！` 中只执行首个括号标签；标签从显示台词和 TTS 输入移除。左右单眉指令为规则控制，当前参考客户端没有句内多段表情编排。
- TTS 仅返回并播放音频，不自动生成或同步口型；`speech_style` 字段也不证明所接 TTS 支持相应情绪。

依据：[接口](https://github.com/AaBb-coder/LumenAct/blob/ad933bce20f0567e4ab4d97be306e39997310a21/docs/API.md)、[资源格式](https://github.com/AaBb-coder/LumenAct/blob/ad933bce20f0567e4ab4d97be306e39997310a21/docs/FORMAT.md)、[公开运行时范围](https://github.com/AaBb-coder/LumenAct/blob/ad933bce20f0567e4ab4d97be306e39997310a21/docs/BOUNDARIES.md)。

### 6.2 自有角色与 Live2D 的接入判断

**3D：**可以复用语义选择、表演曲线和播放逻辑。目标角色需有对应面部形态键及正确形变，按通道含义/名称与数值范围映射。官方推荐在 Blender 中以参考脸对照自有 VRM，通过 MCP 辅助建立缺少的形态键，再人工逐项和组合修正。基础面部形态键驱动不要求全身骨架；头部/眼球控制另看目标绑定。网页没有自定义模型导入或自动适配器，教程中的联动校准面板由使用者生成。依据：[适配教程](https://github.com/AaBb-coder/LumenAct/blob/ad933bce20f0567e4ab4d97be306e39997310a21/docs/ADAPTING_YOUR_MODEL.md)。

**Live2D（我们的接入建议）：**优先复用“自然语言 → 表情类别”的结果，再映射到角色已有 exp3/motion3 预设。后续需要更细控制时，再评估部分曲线到 Cubism 参数的映射；公开包未提供 Cubism 适配，不要求 Live2D 实现全部 166 列。

**对预设库的作用：**制作阶段批量生成、预览和调整预设；运行阶段从自然语言选择合适预设并过渡。LumenAct 为后半段提供了具体候选，也有可复用素材。角色建立兼容控制后，可先复用已有选择模型，无需先为每个角色重训。扩充动作和语义覆盖是否需要改目录或训练，依实际输入效果判断。

### 7.2 Tripo + GPT/Astra 的部件制作路线

找到与用户描述吻合的 [Tripo 官方角色教程](https://www.tripo3d.ai/zh/blog/gpt-6-astra-3d-character-workflow)，页面标注更新于 2026-11-16。流程为：完整角色图 → 分别准备身体、无发头部、头发参考图并补全遮挡 → Tripo 分别生成 3D 部件 → Astra 经 Blender MCP 辅助组装、复用/补充绑定、制作表情与动画。此处拆分的产物是部件参考图，教程未承诺导出完整分层 PSD。

教程给出复用 Tripo 带绑定 GLB 身体的路线，并区分独立表情切换与连续面部形变；连续眨眼等需要实际眼睑几何和形变。动画可导入既有动作或辅助制作关键帧。其角色图、问候与面部特写为独立演示素材，不能把网页拼接效果当成同一角色全流程复现记录。创作者原帖链接可定位，但本轮 X 页面访问被拒。

对 Momo 的价值判断：拆开头部/头发后可分别修正脸部表情和头发结构，再导出可用资产；模型制作与日常运行分开，不要求聊天时常驻 Tripo 或 Blender。资源格式、角色质量与具体服务成本在选型/试做时确认，当前未购买或调用生成服务。

### 7.3 需求与接口建议

角色能力研究同时覆盖资产制作、预设表演、实时动作驱动。保留按已支持能力请求动作/目标、更新或结束动作、反馈当前表现的接口方向；哪些驱动支持自然语言、位置目标、骨骼流或预设播放，按实际提供器定义。暂不锁定 ADRY，不把多个模型都设为默认常驻，也不预先融合项目。优先验证单个角色的基础动作衔接，再判断是否需要实时生成。
