# F-005 · 体验驱动的偏好成长

| 项目 | 内容 |
|---|---|
| 状态 | 待验收 · 额外窄修复后最终 Reviewer PASS；专项 24、联合回归 152 |
| 适用范围 | 仅社交卡 |
| 优先级 | 后续 |
| 前置依赖 | F-002、F-003 稳定运行并产生可靠体验 |
| 后续依赖 | 待设计的共用角色判定框架 |

## 1. 产品目标

让角色在有来源的真实生活体验中逐渐形成和调整具体偏好，例如从“没喝过抹茶拿铁”到“尝试过，并发现自己喜欢低甜、茶味明显的版本”。

偏好成长必须保持核心人格稳定、变化有限、证据可追溯且允许纠错。它不是用户画像，也不是让角色逐渐迎合用户。

## 2. 四层偏好模型

### 2.1 核心人格与边界

相对稳定且默认不允许后台自动改写，例如重视真诚、性格慢热、生活方式偏安静、反感严重剧透、食物过敏或价值观边界。

- 普通生活体验不能改变核心人格；
- 偶尔出现与核心倾向不同的具体体验，可以作为例外；
- 大量体验持续与核心设定冲突时，只标记待确认，不能偷偷改写 Persona；
- 用户或角色创建者可以锁定核心项。

### 2.2 长期口味倾向

变化缓慢，例如偏好低甜饮料、喜欢慢旅行、通常偏爱舒缓音乐、对推理题材感兴趣。

长期倾向只能由多个对象、不同时间或不同情境中的一致体验逐渐形成或修正。单次体验不得重写上层类别。

### 2.3 具体对象与属性偏好

针对具体作品、饮料、地点、活动、版本或属性形成的判断，可以自然成长，例如：

- 喜欢某家店的低糖抹茶拿铁；
- 喜欢茶味明显、甜度较低的饮料；
- 喜欢某一部推理剧，但不代表喜欢全部推理作品；
- 不喜欢某家店的咖啡，不代表讨厌咖啡。

这是第一版主要建模对象。

### 2.4 临时需求与状态

今天很累所以不想看剧、天气热突然想喝冰饮、最近工作多暂停阅读，属于当前状态和情境，不是永久偏好。

- 临时需求可以影响当次选择；
- 不能直接写入长期偏好；
- F-006 提供的状态与 F-005 的稳定偏好必须分离。

## 3. 体验证据

偏好变化必须关联真实体验，不能由模型在没有体验事件时自行宣布。

一次体验至少记录：

- 体验对象、具体版本与上层类别；
- 发生时间、地点和来源事件 ID；
- 实际发生的行为与有效投入时间；
- 是否首次体验；
- 当时天气、活动和角色状态等必要情境；
- 对不同属性的正面、负面、中性或混合感受；
- 一次性的整体印象；
- 是否愿意再次尝试及条件；
- 用户推荐、角色预设或自主选择等来源；
- 证据来源、可信度和幂等 ID。

示例：

```yaml
object: 抹茶拿铁
variant: 某店低糖版
occurred_at: 2026-07-11T15:30:00+08:00
source_event: daily_activity_42
behavior: 喝了一杯
context:
  weather: 炎热
  character_state: 有点疲惫
  first_try: true
attributes:
  sweetness: positive
  tea_flavor: positive
  milkiness: negative
overall_impression: 有点喜欢
retry:
  willingness: conditional_yes
  condition: 下次想少奶
source_quality: verified_activity
```

实际行为、当次感受和稳定偏好必须分开保存。“真的喝过”是事实，“这次觉得不错”是一次体验，“长期喜欢”仍需后续证据。

## 4. 偏好状态的多维表示

偏好不能压缩成一条“未知 → 好奇 → 喜欢 → 最爱”的单线状态，也不使用一个喜欢度分数表达全部含义。

### 4.1 接触状态

```text
未知 / 已知晓 / 有兴趣了解 / 计划尝试 / 已尝试 / 多次体验
```

听说过、计划尝试和亲自体验必须区分。

### 4.2 当前评价

```text
未形成评价 / 偏正面 / 偏负面 / 中性 / 矛盾或混合
```

“喜欢茶味但觉得太甜”属于混合，不能被强行压成单一正负值。

### 4.3 稳定程度

```text
一次印象 / 初步倾向 / 相对稳定 / 需要重新评估
```

第一版阈值已锁定：1 个有效独立体验为一次印象；至少 2 个且跨 2 个角色当地日期为初步倾向；至少 4 个、跨至少 3 个当地日期且覆盖至少 2 种可信情境为相对稳定。矛盾证据优先细分范围，否则进入需要重新评估，不即时翻转。

### 4.4 适用范围

偏好结论必须说明作用范围：

- 具体版本；
- 具体对象；
- 对象属性；
- 上层类别；
- 特定时间、天气、地点或状态情境。

具体版本的正面体验不能直接上升为整个类别偏好。

### 4.5 再次体验意愿

```text
愿意 / 有条件愿意 / 尚未决定 / 暂时不想 / 明确不再尝试
```

再次体验意愿与喜欢程度分离。例如本次体验偏负面，但角色仍可能愿意尝试低糖版本。

### 4.6 “最爱”是比较关系

“最爱”只表示在角色已经体验过的可比较对象中，目前最喜欢某一个。只体验过一个对象时不能宣布其为最爱；表达时优先使用“目前最喜欢”，并允许后续变化。

## 5. 偏好形成与归纳边界

第一阶段只记录具体体验，不自动成长长期倾向。

第二阶段可以在有足够证据时形成具体对象或具体版本偏好。

第三阶段只有跨多个对象和情境出现一致体验时，才允许有限归纳到属性或类别，例如从多次体验中形成“偏好低甜、茶味明显的饮料”。

第四阶段，稳定偏好可以作为 F-003 未来选择的参考因素，但不能成为唯一决策依据。角色仍应允许探索、受时间与状态影响，并保留拒绝用户推荐的权利。

第一版只形成具体对象或具体版本结论，不归纳属性类别或长期口味，也不反馈 F-003 调度。后续阶段转换仍需单独产品确认。

## 6. 用户影响与角色主体性

- 用户推荐只能增加角色知道或尝试某个对象的机会；
- 用户喜欢某物不能直接成为角色的正面体验证据；
- 亲密度不能强迫角色接受推荐或改变判断；
- 角色可以尝试后喜欢、保持中立、不喜欢、暂停或拒绝；
- 用户可以纠正事实，但不能命令系统把角色感受改为“喜欢”。

F-005 建模的是角色自己的体验结果，不是用户偏好，也不是用户画像。

## 7. 矛盾体验与变化

新体验不得覆盖旧体验，所有有效经历按追加方式保存。

当新体验与旧偏好不一致时，依次考虑：

1. 是否属于具体例外，例如通常不喜欢甜饮，但喜欢某一款；
2. 是否需要拆分属性，例如喜欢茶味但不喜欢甜味；
3. 是否需要拆分情境，例如夏天喜欢冰饮、冬天不想喝；
4. 是否只是一次异常体验；
5. 是否存在足够多样化证据支持真正变化。

矛盾首先用于细化理解和降低确定性，不立即翻转偏好。

## 8. 防止自我强化与模型自证

### 8.1 调度—体验循环

系统不能因为角色已有轻微倾向就不断安排同类活动，再把重复安排当成更多独立偏好证据。

- “被安排”不等于“喜欢”；
- 选择行为、实际体验和体验评价必须分离；
- 同一对象、同一来源和同一情境的重复体验不能被视为完全独立证据；
- F-003 需要保留适度探索空间，防止已有偏好垄断全部生活时间。

### 8.2 Persona—生成—回写循环

Persona 先验、真实体验事件和模型产生的主观解释必须分别标记来源。

- Persona 提供“可能喜欢”的先验，不是新体验；
- 真实活动只证明事件发生，不自动证明喜欢；
- LLM 对体验的解释是有限主观记录，不能给自己重复作证；
- 同一生成结论不得通过摘要、记忆和偏好系统多次计入证据。

## 9. 纠错、查看与回滚

用户可以纠正：

- 体验对象或具体版本；
- 发生地点和时间；
- 角色曾经说过的事实；
- 记忆中错误的属性和来源。

错误体验失效后，系统应依据剩余有效证据重新计算当前结论，而不是只修改显示文字。

后续前端可以提供：

- 查看主要当前偏好；
- 展开查看形成原因；
- 删除明显错误的体验；
- 锁定核心 Persona 倾向；
- 重置自动成长产生的偏好；
- 关闭偏好成长。

历史记录应保留来源与失效状态，避免静默覆盖导致无法审计。

## 10. 存储、整理与运行时检索

完整体验历史只保存在数据库中，不得每轮全部进入 prompt。

系统为每个具体对象、属性或类别维护一个可重算的“当前结论”，并保留代表性证据指针：

```yaml
subject: 抹茶饮料
current_view: 偏好低甜、茶味明显的版本
direction: positive
stability: 初步倾向
confidence: medium
evidence_count: 3
evidence_ids: [exp_12, exp_19, exp_27]
```

运行时检索顺序：

1. 优先使用明确对象 ID、生活线 ID 或活动引用；
2. 按类型、状态、时间和情境进行确定性过滤；
3. 必要时再使用语义检索补充；
4. 只向当前任务提供少量相关结论；
5. 用户询问“为什么”时，最多补充少量代表性体验；
6. 没有相关偏好时整个区块省略。

第一版不提前锁死 Top-K，但必须设置固定条数和 token 预算，不能随数据库增长扩大 prompt。

F-005 不在每轮聊天运行。只有新体验产生、事实被纠正、偏好被重置或后台需要重新整理时，才处理相关对象及少量关联证据。

## 11. 与其他功能的关系

### F-002 DailyAgent

提供真实时间、地点、活动和必要情境，不直接形成偏好。

### F-003 持续生活线

产生可验证的阅读、追剧、创作或后续扩展体验；未来选择项目时可以读取少量稳定偏好，但不能因偏好循环制造重复证据。

### F-004 分享储备

可以引用真实体验和当前结论形成分享候选，不反向修改偏好。

### F-006 角色状态机

提供当时的精力和状态。临时状态不能被误写为永久偏好。

### F-007 上下文仲裁

决定当前对话是否需要检索偏好、使用何种粒度和是否补充形成原因。

### Persona

提供稳定核心与初始倾向，不保存自动成长的当前结论，也不被后台自动重写。

## 12. 判定机制待办

本功能已确认判定框架需要处理：

1. 哪些体验有资格成为偏好证据；
2. 同类重复体验如何去重或降权；
3. 证据需要多少对象、时间和情境多样性；
4. 如何从一次印象进入初步倾向或相对稳定；
5. 矛盾体验如何影响稳定性、范围和再次体验意愿；
6. 何时允许从具体对象归纳到属性或类别；
7. 何时需要额外 LLM 调用，何时使用确定性规则；
8. 如何记录变化理由、抑制理由和重算过程；
9. 如何与 F-003、F-004、F-007、后续关系世界模型共用候选和检索机制。

第一版采用确定性资格门槛、独立体验桶、当地日期与可信情境阈值，不使用喜欢度加减分，也不让 LLM 自由决定稳定程度。属性类别归纳、长期口味和调度反馈继续后置。

## 13. 第一版验收方向

- 能区分核心人格、长期倾向、具体偏好和临时需求；
- 每条偏好变化都能追溯到真实体验；
- 同一体验不会重复更新；
- 能区分听说过、计划尝试、真实尝试和多次体验；
- 能表达正面、负面、中性和混合评价；
- 单次异常体验不会重写整个类别；
- 用户推荐不会直接让角色喜欢；
- 删除错误证据后能够重算当前结论；
- 重启与跨日后状态保持一致；
- 运行时只检索与当前任务相关的少量结论；
- 角色可以解释偏好为何变化，但不会机械报告内部状态；
- 不发生调度自我强化、Persona 自动漂移或用户迎合。

## 14. 研究依据与可借鉴方向

- ACL 2026 `Beyond Static Persona Consistency: Dynamic Persona Coherence in LLM Role-Playing`：支持将稳定身份与随历史变化的适应层分离，避免角色僵化和 Persona 漂移。
- ACL 2024 `InCharacter: Evaluating Personality Fidelity in Role-Playing Agents through Psychological Interviews`：角色成长后仍需验证人格层面的长期一致性。
- ACL 2025 `In Prospect and Retrospect: Reflective Memory Management for Long-term Personalized Dialogue Agents`：支持保留不同粒度的历史证据并根据当前任务检索，而不是每轮读取全部历史。
- SIGIR 2018 `Attentive Recurrent Social Recommendation`：长期稳定兴趣和时间动态兴趣需要分开建模；该结论来自用户推荐领域，只作为结构参考。
- RecSys 2021 `Soliciting User Preferences in Conversational Recommender Systems via Usage-related Questions`：具体使用情境比抽象询问更容易获得丰富偏好信息；Skyler 将其改造为角色自身体验建模。
- Nature Human Behaviour 2024 `Comparing Experience- and Description-based Economic Preferences across 11 Countries`：人的价值与选择明显受体验和情境影响，反对无情境的绝对偏好分数。
- NeurIPS 2024 `Preference Learning of Latent Decision Utilities with a Human-like Model of Preferential Choice`：简单标量偏好模型难以覆盖真实选择中的情境效应。
- Communications Psychology 2025 `Action repetition biases choice in context-dependent decision-making`：重复选择本身会影响后续偏好，提示必须防止调度—体验—偏好的自我强化循环。

现有研究主要建模用户偏好或静态角色一致性，直接研究“虚拟角色依据可验证的持续生活体验形成自身偏好”的工作仍然有限。本功能具有研究潜力；第一版现已进入实现，仅覆盖可追溯的具体对象/版本结论。
