### 学习反馈子任务

先用 dsh-agent-growth 加已有来源读取/监控和麦麦回传，执行“学习仓库新增一版资料 → 读新增内容 → 对照 Skyler 需求给出带出处的建议 → 回发起私聊”。重复提供同一个版本，检查不会重复学习/反馈。沿用已有局部测试记录，新的联测分别记录读取、模型判断、保存及回报结果。用户要求整理到知识或实验仓库时，再按其授权验证产物。

## 任务交付方式

每项任务一旦复现缺口，就按需求和通过条件形成小批改动并回归；无需等待 T-01 至 T-08 全部完成。T-09 只安排正式前端与资产整合。

每项输出：需求 ID、实际版本/配置、输入与操作、预期、实际、证据位置、结论、下一步。通过、失败、待设备、待用户体验分别记录。按[设备验收清单](SKYLER-5070TI-ACCEPTANCE.md)执行，写入[验收日志](SKYLER-VALIDATION-LOG.md)。

两台 Codex 以同一文档/代码提交为输入，按运行设备和文件责任分工。文档与代码通过 Git 共享；密钥、真实聊天库、音频和模型按实际数据交接另行处理。一次交付后更新状态，只有新变化或具体失败才扩大回归范围。
