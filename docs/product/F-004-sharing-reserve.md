# F-004 · 分享储备与主动分享

| 项目 | 内容 |
|---|---|
| 状态 | 待验收 · Extra Narrow 最终 Reviewer PASS |
| 适用范围 | 仅社交卡 |
| 优先级 | 中 |
| 前置依赖 | F-002、F-003 |
| 后续依赖 | F-007、F-008，以及待设计的共用角色判定框架 |

## 1. 产品目标

角色在正常生活中经历值得说的事情时，先形成可追溯的分享储备，再通过当前对话中的自然入口或一条克制的主动消息与用户分享。

本功能的目标不是把 DailyAgent 变成定时播报器，也不是建立新闻推荐系统，而是让角色的真实生活进展能够与双方的共同历史发生连接：角色会因为一件事想到用户，分享以后又能把用户的回应接回后续生活。

## 2. 第一版核心原则

### 2.1 真实经历先于分享

- 第一版分享候选只来自 F-003 已发生并完成结算的持续生活线事件。
- 日程中写了“看剧”“画画”或“去咖啡店”不代表事情已经发生，不能仅凭计划产生分享。
- F-002 计划、current_activity、普通过去日程与天气第一版都不产生候选；F-004 不反向修改 F-003 真源。

### 2.2 分享是关系连接，不是信息分发

第一版优先支持：

- 角色在经历某件事时想到用户；
- 延续用户推荐、双方约定或之前未聊完的话题；
- 分享角色本人觉得有趣、意外、好看或想吐槽的生活片段；
- 角色真诚希望听听用户的看法；
- 发现少量确实与用户当前需要相关的内容。

“对用户有用”不能成为唯一标准。没有实用价值但能体现角色生活和关系连接的小事，也可以成为分享候选。

### 2.3 推荐创造机会，不创造义务

- 用户推荐的作品可以在角色真实尝试后形成高关系连接的分享候选。
- 用户说“继续看”“下次试试”不等于强制任务，是否进入日程和推进仍由 F-003 决定。
- 角色达到双方约定的后续条件后可以再次形成候选，但不能为了履约伪造进度。

### 2.4 候选不等于必须发送

- 储备存在不代表立即分享。
- “继续等待”“放弃”和“自然过期”都是正常结果。
- 没有合适入口时，不为清空队列强行插入话题。

## 3. 第一版候选来源

### 3.1 纳入第一版

- F-003 持续生活线产生的真实阅读、追剧和创作体验；
- 用户推荐内容出现的真实后续；
- 双方已有共同话题达到明确的新节点；
- 用户明确要求角色在某个真实条件满足后回来分享。

### 3.2 后续阶段再扩展

- 角色主动联网发现新剧、新书、音乐和新闻；
- F-002 普通日程、旅行、天气和 current_activity 自动转成经历；
- 高频资讯推荐和每日简报；
- 未经约束的内容搜索与自动订阅；
- 依靠联网搜索永久改变角色兴趣。

现实外部内容进入候选时，必须保留标题、来源、发布时间、链接和查询时间；搜索结果不能冒充角色亲自阅读或观看过的体验。

## 4. 分享候选结构

候选保存“发生了什么、为什么想分享、有哪些表达边界”，不提前保存一条固定文案。

至少记录：

- 来源事件、生活线或外部内容 ID；
- 已确认的可分享事实；
- 角色当时的有限体验或感受；
- 分享动机；
- 与用户的关系连接及其来源；
- 产生时间、建议有效期和状态；
- 适合与不适合的语境提示；
- 剧透等级、敏感等级和禁止表达内容；
- 允许的输出媒介；
- 首次分享时间、用户是否回应和后续条件；
- 来源与版本，便于追溯和纠错。

示例：

```yaml
event: 看完《某部剧》第五集
source: F-003 真实进度结算
experience: 对结尾感到意外
motive: 延续共同话题
relationship_anchor: 用户推荐，并曾说看到第五集后再聊
safe_facts:
  - 已看完第五集
forbidden:
  - 不透露具体结局
possible_modalities:
  - text
status: waiting
```

## 5. 生命周期

```text
真实事件发生
  → 产生分享候选
  → 进入储备
  → 等待自然入口或主动分享机会
  → 已分享 / 已放弃 / 已过期
  → 记录用户回应和后续条件
```

第一版至少支持：

- `waiting`：等待合适机会；
- `shared`：已经首次分享；
- `dismissed`：明确放弃；
- `expired`：自然过期；
- `superseded`：被同一生活线的新进展覆盖。

同一候选不得重复主动发送。新的真实进展可以产生新候选，但不能复活旧候选伪装成新消息。

## 6. 两种分享出口

### 6.1 对话内自然分享

用户正在与角色聊天，当前话题出现自然入口时，F-004 提供少量相关候选，由 F-007 决定是否引用并按 Persona 自然表达。

典型入口包括用户询问角色近况、再次提到相关作品、轻松话题空档或共同约定被明确提起。

第一版采用 10 分钟的对话候选 offer lease：同一候选刚提供给某轮判定后，
短时间内不会在连续同话题轮次反复注入。offer 只表示“本轮模型可以参考”，
不等于角色已经实际分享，不能提前写成 `shared`。在没有可靠的生成后引用回传
时，候选继续保持 `waiting`；lease 只负责短期防重复，超时后允许重新判断。

### 6.2 主动消息

双方没有正在聊天时，角色可以对少量高价值候选发起一条主动消息。

- 主动消息不能作为每天必须完成的任务；
- 用户未回复时不得催促或重复发送；
- 睡眠、静默时间、用户明确忙碌和主动分享关闭时必须抑制；
- 每用户×角色独立设置，默认关闭；用户明确开启后才生效；
- 当地 23:00–08:00 默认静默；最近用户消息 90 分钟内不另起话题；
- 自然模式最多 2 次/自然日，两次至少间隔 6 小时；这是上限，不是发送配额；
- 上一条主动分享没有得到该用户对该角色的后续消息时停止继续发送；
- 对话内自然分享不计主动消息配额，每轮最多一个辅助 SHARE，且先处理用户主需求；
- 前端后续可提供关闭、克制、自然、活跃四档。

## 7. 分享后的共同话题闭环

分享不是终点。用户的真实回应可以形成共同话题、后续约定、候选输入或边界。

### 7.1 继续讨论

用户愿意继续聊时，对话与原始事件保持关联，避免后续摘要把同一共同话题拆成无关片段。

### 7.2 后续约定

例如“看到第八集再来找我”应保存为轻量的结构化触发条件：

```yaml
topic: 某部剧
origin: 用户推荐
current_progress: 第五集
follow_up_condition: episode >= 8
status: waiting_for_progress
```

F-003 负责真实推进并报告条件是否满足；F-004 负责在满足后产生新的分享候选。约定不直接修改日程。

### 7.3 新信息与推荐

- 用户提供的现实作品信息在验证前只作为待确认信息；
- 用户推荐的新作品进入 F-003 候选池，不立即变成进行中项目；
- 用户对一次分享的回应不能直接改变角色永久偏好，偏好演化属于 F-005。

### 7.4 不感兴趣、无回应与纠正

- 用户明确不感兴趣时停止当前分享，并记录清晰边界；
- 用户没有回应时只表示“没有证据”，不能推断为讨厌或关系下降；
- 用户纠正来源、约定或共同历史时，错误锚点必须失效，并保留纠正来源。

## 8. 输出媒介

F-004 决定“为什么、何时、分享什么”，不绑定具体媒介实现。

### 8.1 第一版

- 自然文字为核心输出；
- 现实外部内容可以带来源链接卡片；
- 现有 TTS 可以朗读最终文字，但不参与分享决策。

### 8.2 F-008 接入后

- F-004 可以把 `generated_image` 作为允许媒介交给 F-008；
- 第一阶段优先支持角色创作、心情插图等表达型图片；
- 生活照片型图片必须受到角色外观、当前地点、时间、天气、活动和视觉连续性的共同约束；
- 生成图片不得作为现实事件或外部新闻的证据，后台必须保留生成来源。

F-008 只负责生成与返回媒体，不决定是否应该分享。

## 9. 用户控制

社交卡应允许用户控制：

- 是否允许角色主动分享；
- 静默时间；
- 大致频率；
- 是否允许联网内容；
- 剧透边界；
- 某类内容是否停止主动发送。

用户通过自然语言表达的明确边界应与前端设置使用同一约束来源。设置和清晰边界属于硬约束，不由模型临时绕过。

## 10. 功能所有权

| 内容 | 所属功能 |
|---|---|
| 角色是否真实看完、读完或完成某个进度 | F-003 |
| 是否形成分享候选、是否已分享和是否过期 | F-004 |
| 用户要求达到某个进度后再聊 | F-004 后续约定 |
| 角色是否继续项目 | F-003 |
| 多次体验是否改变角色偏好 | F-005 |
| 当前如何自然表达 | F-007 |
| 图片如何生成 | F-008 |
| 用户回应背后的心理状态推测 | 后续关系世界模型 |

F-004 的操作记录不应全部进入长期记忆。长期记忆只保留有持续意义的共同经历、明确约定和用户边界。

## 11. 判定机制边界

本需求已经确认需要一套可复用、可解释的角色判定框架，但当前尚未定稿具体算法。

后续统一讨论：

1. 候选如何从真实事件中产生；
2. 哪些硬条件直接禁止分享；
3. 关系连接、角色在意程度、新鲜度、话题适配、重复风险和打扰成本如何比较；
4. 对话内分享与主动消息是否使用不同策略；
5. 程序规则、策略模型和主 LLM 分别拥有哪一部分决策权；
6. 如何记录决策理由、抑制理由和用户反馈；
7. 如何控制额外调用、tokens、延迟和随机性。

在该框架定稿前，不使用任意加权总分或“让 LLM 自由决定”冒充完整判定机制。

## 12. 第一版验收标准

- 只有真实结算的经历或已验证事实能够进入储备；
- 候选可等待、分享、放弃、过期、覆盖和去重；
- 储备存在不会强制角色立即发送；
- 同一候选不会重复主动分享；
- 用户未回复时不会催促，也不会自动形成负面偏好；
- 明确后续约定能够在 F-003 达到真实条件后重新产生候选；
- 用户推荐、边界和纠正能够进入正确的数据所有权，不污染项目进度；
- 对话内分享与主动消息共用真实性标准；
- F-004 不依赖 F-008 也能完成文字分享闭环；
- 图片接入后不会把生成内容当作现实证据。

## 13. 研究依据与可借鉴方向

- ACL 2023 `Controllable Mixed-Initiative Dialogue Generation through Prompting`：主动权和交流策略应由策略规划控制，再由生成模型表达。
- ACL 2023 `Knowledge-enhanced Mixed-initiative Dialogue System for Emotional Support Conversations`：混合主动交流具有价值，但主动行为需要独立的分析和评估。
- CoNLL 2025 `Interpersonal Memory Matters` / MapDia：长期人际记忆可以支持主动话题恢复，但现有工作主要从旧聊天检索话题，尚未覆盖角色聊天外持续发展的真实生活线。
- NAACL 2025 `Towards Lifelong Dialogue Agents via Timeline-based Memory Management` / THEANINE：时间和因果链比孤立记忆更适合表达长期变化。
- ACL 2022 `Multimodal Dialogue Response Generation`：文字或图片应被视为可选择的对话动作，而不是每轮固定同时输出。
- ACL 2023 `MMDialog`：大规模真实对话证明图片回复是开放域交流的重要组成，但相关性和时机仍是核心问题。
- ACL 2024 `Evaluating Very Long-Term Conversational Memory of LLM Agents` / LoCoMo：长期多会话中的时间、因果和多模态一致性仍明显困难。
- EMNLP Findings 2024 `Stark`：开始研究长期、Persona 相关的图片分享，但没有覆盖由可验证日程和生活进度驱动的分享储备。

这些研究支持 F-004 的基本拆分，但不直接提供可以照搬的完整判定框架。
