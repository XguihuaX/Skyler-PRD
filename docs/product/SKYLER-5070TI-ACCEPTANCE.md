# Skyler · 5070 Ti 装机验收与 Mac 联合开发

2026-11-22。对应 Skyler PRD v0.95。以下均为目标设备待测项。这份清单可以单独交给主机上的 Codex。麦麦负责主人私聊、人格、记忆、历史与日程，选中的 DSH 插件在 DSH 中运行。装机后的第一个交付物是一段可在主机和 Mac 接着聊的真实私聊，以及这段对话的验收记录。

## 第一轮先跑麦麦原版

**Mac 基线先验。** 本次复核的 v1.4.8 官方桌宠文档提供 macOS 构建，同时注明上游尚未进行 Mac 实机验证；Mac 的应用条件按进程名匹配。第 2 项验证实际安装、连接与历史同步，主屏测试另核对 Mac 屏幕录制授权。主机后台能启动不代表 Mac 客户端及本机设备链路已通过。[上游平台说明](https://github.com/Mai-with-u/MaiBot/blob/v1.4.8/docs/desktop-pet.md#截图授权与平台限制)

| 顺序 | 怎么测 | 通过时应看到什么 |
| --- | --- | --- |
| 1 · 主机启动 | 记下主机系统、实际安装的麦麦版本或提交、Bot、启用的模型及本地或远程位置。启动麦麦和目标 Bot，从主机 WebUI 私聊发送一个临时记号，要求回复。重启服务后回到该私聊。 | 收到真实模型回复，重开后原消息和回复还在。记下消息时间与启动错误。现有调查基于 v1.4.8；实装版本有差异时以主机行为为准。记录空闲内存、显存作后续对照。使用远程文字模型时，GPU 推理留到本地语音模型运行时验证。 |
| 2 · Mac 接同一个 Bot | 在 Bot 设置打开桌宠并选远程模式（v1.4.8 为 `desktop_pet.enabled=true`、`desktop_pet.mode=remote`）。Mac 官方桌宠选择“通过 WebUI 连接”，填 Mac 可达的主机地址，登录后选同一个 Bot。先读主机发的记号，再从 Mac 发另一个，在主机网页查看。关闭并重开 Mac 客户端。 | 两端看到同一主人私聊里的两组消息，重开仍能继续。收起、展开聊天面板能回到刚才的位置。主机网页可与 Mac 桌宠并用；同一 Bot 的原版桌宠一次只接一个客户端。若用手机浏览器，再做一次网页回看。 |
| 3 · 人格与记忆 | 沿用麦麦完整角色配置，查清 A_Memorix 和纠错相关开关。用虚构偏好测试一次写入、隔段对话后按需召回、在聊天里纠正，以及从设置查看、编辑和删除。分别试“她刚提到就纠正”和“她没提到时主动纠正”。 | 记录哪种输入真正改变了可召回的记忆。在近期上下文已移出或用独立检索复查时，生效的新偏好可被找到，已删的测试记忆不会再被检出。用“去上海两天”回放短期事件，以原声明的期限推断，允许新消息修正。 |
| 4 · 日程 | 在同一私聊设一个几分钟后的提醒，再分别试改期、取消、重启后到点提醒。用可控的前台应用事件试一次条件提醒。 | 各项只在正确条件和时间触发，改过的旧时间、取消的事项不会再报。记录离线后恢复时过期提醒的实际行为，过期本身不能证明用户参加过活动。 |

首次优先完成 1、2。若 Mac 连不上，先区分主机 WebUI 是否可达、是否登录成功、是否选对 Bot、是否已有另一个桌宠占用。把具体故障交给对应设备上的 Codex，再接 DSH。[麦麦桌宠连接说明](https://github.com/Mai-with-u/MaiBot/blob/v1.4.8/pet-clients/desktop/README.md#L7-L16) · [原版桌宠与主人会话](https://github.com/Mai-with-u/MaiBot/blob/v1.4.8/docs/desktop-pet.md)

## 主机与 Mac 计划交接验证

2026-11-22 用户确认先验证出差前交接、返程交回。完成上面第 1–4 项后，用测试角色与数据跑基础往返；DSH 接入后另补它的任务和插件状态，不把完整业务插件全部通过作为基础交接的前提。需求见 [PRD §5.12](SPEC-momo-next-details.md#512-主机与-mac-的计划交接2026-11-22-已确认验证方向)。

| 步骤 | 动作与通过条件 |
| --- | --- |
| 准备 | 两端记录版本、模型位置和实际数据目录。测试角色保存偏好、两条历史、一个小文件和一条提醒；确认待交接范围。用上游迁移机制准备可恢复副本，核对 Mac 的路径与依赖。 |
| 交给 Mac | 停止主机上该角色的消息处理与提醒执行，完成数据交接并启动 Mac 服务。主机关机后，Mac 仍能回复、回看历史、召回偏好和打开测试文件。记录当前运行端。 |
| 出差期间 | 在 Mac 新增一句话、纠正偏好、修改提醒；核对实际保存及到期只提醒一次。手机与微信在对应入口已接入后分别测试，记录是否需要重连或扫码。Mac 休眠及主机专属能力不可用的状态如实记录。 |
| 交回主机 | 停止 Mac 侧该角色的执行，交回最新数据并启动主机。核对新消息、更正后的偏好、文件和提醒状态；Mac 恢复客户端后能继续聊，旧副本不覆盖新数据。 |
| 后续扩展 | DSH 接入后单独核对其任务、插件数据、账号连接及运行中任务处置。失败时留下步骤、错误和可恢复副本，不把未恢复任务记为完成。 |

当前全部待测。测试用短时间间隔回放，不要求等待真实一周；自动故障接替未选定。

## 接入一项，验证一项

## 多人语音单独测

先跑通单人 ASR，再使用同一份有人工标注的双人普通话夹英文录音。两人按 A、B、A 的顺序轮流说话，另留一小段重叠讲话单独观察。先试 DSH 的 `dsh-speech` 0.4.0；本地中继模式要求识别服务会返回声纹向量。需要比较保留 faster-whisper 的路径时，用 WhisperX 处理同一份录音。已有模拟向量回放得到 A、B、A，真人表现仍待测。[插件本地识别服务要求](https://github.com/agent-mobile/dsh-speech/blob/008b06fa0e181a9de01e69af38988fe8c7733c9c/README.md#L179-L189) · [WhisperX](https://github.com/m-bain/whisperX)

记录转写错词、每句归属是否正确、换人时是否串号、标记能否进入麦麦的同一段聊天，以及相对基础 ASR 增加的延迟、RAM 和显存。无法判定时保留未知。识别已登记的本人、重叠语音分别转写、是否回应旁人是三个独立问题。根据实测再定是否在 Skyler 常规语音里启用。环境声分类、角色制作与动作驱动、推理前缀实验有各自的研究安排。Life、DailyAgent、多角色及运行中追加要求的增强后置。上网学习并回原聊天反馈已列入需求，排期待定。

## 两台 Codex 怎样一起做

1. **交接同一份需求。** 需求材料集中在 Skyler-PRD 仓库；首次验原版先阅读主 PRD、任务与本清单。正式联合开发时，两台机器使用同一份 Skyler 仓库和已共享的提交，以仓库相对路径交接需求、案例和改动。麦麦原版另放一个目录并记录上游版本。真实配置、密钥、录音、聊天库和模型权重不通过 Git 共享；计划交接时按所需范围传送业务数据，目标机器的凭据与模型依赖单独核对。
2. **按运行位置分工。** 主机 Codex 负责麦麦、DSH、GPU 模型和主机日志。Mac Codex 负责客户端、Mac 本机采音/播放/屏幕、需求与代码评审，并在计划交接验证时负责 Mac 本地服务端与恢复日志。联测时一端发出带唯一记号的动作，另一端核对输入、落库及回执。并行改代码时，两端各管一组文件，在各自分支工作，合到约定版本后用相同用例回归。
3. **坐在 Mac 前也能操作主机。** 两端使用支持该入口的桌面应用、登录对应账号和工作区，主机保持在线。在主机的 Settings → Connections 允许远程连接，再从 Mac 的 Control other devices 选择主机和项目。也可连接已配置 SSH 并已登录 Codex 的主机。主机会话操作主机上的文件、服务与显卡，Mac 本地会话操作本地设备。需求文件仍用上一步的方式共享。[Codex 跨设备连接](https://learn.chatgpt.com/docs/remote-connections)
4. **以一次可复现的结果交接。** 建议每项留一行记录。字段为用例号、日期、执行机器、麦麦/插件版本、Skyler 提交（如有）、输入、预期、实际、证据位置、结论、下一步及负责人。例如“第 2 项，主机收到 Mac 第二个记号，Mac 重开后可回看，附双方消息时间”。目标机观察到结果后再记通过。遇到差异先核对配置或换现成入口，再按复现结果决定二开。提交、推送按项目约定分别授权。
