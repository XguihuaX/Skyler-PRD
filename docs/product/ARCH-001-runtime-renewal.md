# ARCH-001 · Skyler 当前架构与接入方向

2026-11-22 · 对应 PRD v0.96。本文记录已定分工、接入建议和待验证点。早期重建执行核心、拆取麦麦组件、DSH 底座等比较保存在[历史架构记录](HISTORY-runtime-renewal-20261122.md)，不再作为当前实施指令。

## Skyler 基于麦麦二开的分工建议

已定方向为以麦麦作为 Skyler 主程序，已有能力直接采用，适合 DSH 的任务按需委托。Skyler 是新版产品名，旧 Momo 提供客户端与资产候选；无需为三者各建一套独立的角色对话和记忆系统。

| 部分 | 当前职责 | 接入时需要核对 |
| --- | --- | --- |
| 麦麦 | 主人私聊、人格与配套 Prompt、近期和长期记忆、聊天历史、日程、查询子代理、插件及 MCP | 实际版本、记忆开关、聊天身份、事件与结果回到哪段会话 |
| DSH 与选用插件 | 多步办事、办公、网页/电脑操作、周期或事件任务，以及已有账号授权和单次确认 | 实际使用的会话是否加载所需插件，审批是否等待用户，任务状态/停止/成果是否回传 |
| 客户端 | Mac/手机的输入、采音、播放、屏幕或摄像头、窗口与角色显示 | 设备授权、会话关联、真实播放/收听状态，产物能否从当前设备打开 |
| 旧 Momo 资产 | 角色、Live2D、音色、声音管理及已有客户端实现 | 实测缺口对应的最小复用范围；未批准整体迁移或退役 |

起点见[麦麦能力调查](../INV-42-maibot-capabilities-and-momo-fit.md)与[十域复用总表](SKYLER-FUNCTION-REUSE.md)。接口信息与控制需求见 [INTERFACE-001](INTERFACE-001-frontend-backend-contract.md)，字段和传输协议尚未冻结。

## 模块边界与账号连接

麦麦向 DSH 交付目标、约束和可用资料，DSH 在其会话内执行，结果显式回到发起聊天。入队回执、工具执行状态、实际成果和用户收到成果分别核对。已有 MCP/API 能直接满足需求时直接接入；一个 DSH 工具不必再包装一个同名麦麦插件。

服务账号的登录、重连与权限沿用对应宿主和插件。统一展示账号状态是界面建议，尚未确定页面。微信适配器与内部主人会话身份不同，共享记忆、同一人归属及连续历史需分别验证；不能仅凭接入同一个 Bot 就认为全部合并。[多端入口](SKYLER-CHANNELS-AND-HANDOFF.md)

## 主机与 Mac 计划交接

用户已确认先验证主机 → Mac → 主机：正常由 5070 Ti 主机提供服务，出差前交给 Mac，返程将新数据交回。每次由一个运行端处理同一角色的消息与提醒。

先以测试角色复用麦麦的导出/恢复和换机机制，核对聊天、记忆、文件、提醒及设备相关配置；DSH 接入后再覆盖它的独立任务和插件数据。账号连接、绝对路径、本机或远程模型、运行中任务需分别核对。自动切换和双端同时写入未选定。[产品行为](SPEC-momo-next-details.md#512-主机与-mac-的计划交接2026-11-22-已确认验证方向) · [上游迁移](https://docs.maibot.chat/faq/backup-and-migration)

## 已定位的接入差异

| 条件 | 已核对的差异 | 处理顺序 |
| --- | --- | --- |
| 选用 Tobs v1.7.0 手机通话 | 画面/转写进入它自己的 Bot 私聊；识别后释放用户原声 | 验现有桥能覆盖多少，再补麦麦会话投递和逐条原声保存 |
| 审批经过麦麦 v1.4.8 特定 ACP 回调 | 提供 allow_once 时自动选择允许一次 | 先验实际路由；需要用户确认时选现成等待入口或补转发 |
| 选用所查 voice-mode 0.7.44 | 唤醒每句回待机、硬打断清除余下播报 | 对照一次唤醒连续聊、插问后明确“继续”的目标，选组合或适配 |
| 选用社区 Live2D 桌宠 | 使用独立 deskpet 身份 | 核对与主人聊天历史、记忆及原声的关联 |

这些是特定版本/路径的差异，并非整套系统必须自研的模块清单。其他项先使用候选配置，复现缺口再形成改动。[证据与源码](SKYLER-FUNCTION-REUSE.md#哪些情况实际需要改代码)
