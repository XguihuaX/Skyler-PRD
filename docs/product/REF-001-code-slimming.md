# REF-001 · 代码瘦身与逻辑整合工程规格

> 2026-11-17 主线调整：用户改为以需求驱动重构推进项目，入口为 [Momo 重构 PRD](PRD-momo-next.md)。本文件保留此前精简工作的范围、成果及待验收记录，不再作为继续扩展精简工作的默认任务单；后续重构包含必要的代码整合，范围另行确定。本调整不撤销已有改动，也不将未完成验收标为完成。

日期：2026-10-01。状态：多批主链切口通过定向回归；完整启动、对话与真机体验验收仍在进行。对应 [日常实用助手阶段需求](PRD-assistant-first-2026.md) 的任务 4。本规格是工程工作单，不表示整个项目已经优化完成。

## 1. 目标

让核心路径易于理解和修改：启动、聊天上下文、工具选择与调用、WebSocket 单轮状态、语音捕获/播放。瘦身同时包括减少冗余代码与重复计算、降低可证明的耗时、Token 和资源开销；通过职责分离与清晰的状态边界，降低后续新增邮件、提醒和电脑任务时的回归风险。文件行数是参考指标；最终以可维护性、行为一致性和运行指标验收。

## 2. 工作区基线

- 当前本地工作树已有大量未提交功能代码（审计时 62 个已跟踪文件修改），必须以**当前工作树**为准。不得 reset/clean、覆盖、回滚或顺手整理用户其他改动。
- 当前任务已做第一刀：`backend/main.py` 的 53 个迁移调用及其 TTS cache 依赖被原顺序移至 `backend/database/run_migrations.py`，main 保留 `db_migrations_all` boot mark。新任务先审阅这份未提交 diff，再继续工作；不要重复抽取或重排迁移。
- 已知基线：相关启动检查 11 项通过；`tests/test_ws_helpers.py` 收集时因旧 `_run_plan` 导入失败；此前 `npx tsc -b` 有 3 个未修错误。后续报告应区分既有问题与本轮引入的问题。

## 3. 允许的工作与建议顺序

1. **核对第一刀**：比较迁移执行顺序、TTS cache 加载位置、异常处理和 boot mark；确认模块导入无循环。若发现问题，直接修复。
2. **梳理聊天主链**：绘制 `_build_messages`、工具 schema、工具执行和 legacy fallback 的调用关系。优先抽取可纯函数化或明确独立的片段，合并真实重复逻辑。保持同输入下消息内容、顺序、可用工具集合、工具结果处理与模型调用次数不变。
3. **审查 WebSocket 单轮状态**：识别文本、TTS、打断和持久化的状态转移与重复收尾逻辑。只有在现有回归可覆盖时再拆分，保持音频顺序、取消语义和历史写入不变。
4. **审查前端音频边界**：MediaStream 生命周期、VAD、打断、播放队列与资源释放；针对已确认的重复或资源泄漏给出修复。没有本机 RAM/语音证据时不承诺性能收益。
5. **记录遗留路径**：标出有调用证据的保留代码、无调用证据的候选旧路径及删除条件。删除前先查测试、日志/迁移兼容和外部入口。
6. **量化效率切口**：记录改前与改后的同口径指标，优先检查每轮重复生成工具 schema、聊天上下文耗时、WebSocket 音频/附件处理开销和空闲语音资源。只在不改变输入输出与工具可见集合时做无行为变化的优化；工具按任务筛选须另做质量对照。

每批次只处理一个边界，提交可读的 diff 与验证记录。可以在同一新任务中连续完成多个切口；若一个切口需要产品行为变化，先形成单独决策项，不把它夹在“瘦身”里。

## 4. 不变量和边界

- 不改引擎、真实 boot marks、appReady gate、模型/角色真名和 splash；不伪造进度或完成状态。
- 不改变 Persona、角色状态、记忆来源、短期窗口、摘要或用户数据语义。
- 不改变已配置工具的可见集合、写动作确认门、权限范围和桌面操作策略。按任务筛选工具属于任务 5，需独立质量对照。
- 不改邮件、提醒、电脑连续操作或全双工产品能力；这些属后续工作。
- 不改或 stage `config.yaml`。默认只交 diff，不 commit；没有用户明确要求不 push。

## 5. 验收标准

- 对每个切口给出改前职责图/调用关系、改后边界、删减/移动的逻辑和其存在或废弃证据；不能用“文件变短”代替说明。
- 效率优化须给出改前/改后同口径测量（如耗时分布、每轮 schema Token、内存或 CPU 占用），注明样本、运行环境与行为回归；未测得的收益不标为完成。
- 针对受影响路径运行相关自动检查；应有能识别行为差异的测试或等价的现有回归，不写仅复述实现的测试。
- 启动迁移顺序、boot mark、聊天消息组装、工具调用、WebSocket 中断/收尾和语音资源生命周期不得出现新回归。对无法本机验证的部分列真机验收步骤。
- 运行 Python 语法/导入检查；改动前端时运行默认 `npx tsc --noEmit`，涉及构建路径时运行 `npx tsc -b`，区分既有错误与新错误。
- 每批报告含绝对路径及行号、`rg` 锚点、测试结果、已知限制和真机验收要点。

## 6. 完成条件

完成条件是启动、聊天与记忆、工具、WebSocket、前端语音及初始渲染这几条主链均有调用与职责边界记录；有收益证据的无行为变化切口已实施并通过对应回归；需要改变工具可见集合或兼容语义的切口有独立质量/产品决策记录。完整启动、对话延迟和真机语音/首屏验收未完成时，状态保持“待验收”，不得称整个项目已优化完。
