# F-001 · 时间一致性与对话重返

| 项目 | 内容 |
|---|---|
| 状态 | 已实现 · Reviewer Round 3 PASS · 待负责人真机验收 |
| 适用范围 | 所有卡片 |
| 优先级 | 最高 |
| 依赖 | 现有消息时间戳、短期上下文与摘要 |

## 1. 产品目标

让角色理解一句话发生在什么时候、距现在多久、当前是否仍然成立，以及用户离开一段时间后是否仍处于同一即时对话场景。

目标不是删除旧聊天，而是把内容正确区分为“当前状态”和“历史事件”。

## 2. 核心场景

1. 用户 14:00 说“去工作两个小时”，16:00 后不得继续假定用户正在工作。
2. 用户深夜说“好困”，第二天发消息时不得再问“怎么还不睡”。
3. 用户离开约两小时后回来，角色应意识到经过了时间，不能像只间隔数秒一样无缝接话。
4. 用户明确说“继续刚才的话题”时可以恢复旧话题，但仍应承认中间的时间间隔。

## 3. 功能需求

### 3.1 时间语境

- 每轮计算当前时间、上一轮时间、间隔时长和是否跨日。
- 历史消息继续保留原始发生时间。
- 明确时长优先：如“两小时”“到晚上十点”直接形成有效区间。

### 3.2 临时状态有效性

- “困、吃饭、准备睡觉、正在工作、出门”等即时状态不得永久有效。
- 用户明确结束时立即失效；新事实可以推翻旧事实。
- 没有明确结束信息时，第一版统一使用两小时重返边界作为保守预计期限；后续有真实失败案例后再决定是否拆分类别期限。
- 预计期限到达只表示“不再当作确定的当前事实”，不等于断言现实一定结束。
- 跨日默认关闭昨晚的即时状态，除非用户明确声明会持续到次日。

### 3.3 对话场景边界

- 默认把约两小时作为“需要重新判断是否仍为同一即时场景”的界线，而不是硬删除或强制开新会话。
- 短间隔可自然承接；长间隔由当前消息决定是否继续。
- 跨日默认进入新场景；用户明确引用旧话题时允许恢复。

### 3.4 生成约束

- 回复前向模型提供经过程序计算的时间结论，不只提供原始时间戳。
- 当前消息与有效的当前状态优先于旧聊天的语义惯性。
- 已过期内容只能作为历史背景，不得继续作为当前前提发问或劝告。

## 4. 非目标

- 不新增长期记忆层。
- 不删除或隐藏历史消息。
- 不为助手卡创建虚构生活。
- 不依赖模型自行完成关键的跨日和时长计算。

## 5. 验收标准

- 覆盖“深夜困倦 → 次日上午发消息”的自动测试。
- 覆盖“明确持续两小时 → 到期前/到期后”的自动测试。
- 覆盖“离开两小时后继续/不继续旧话题”两种行为。
- 覆盖跨午夜、时区和无效时间表达的回退。
- 真机聊天中，旧状态仍可被回忆，但不再支配当前回复。

## 6. 当前完成度

- 已有：当前时间注入、历史消息相对日期标注。
- 缺少：时间差结论、跨日失效、状态有效区间、对话重返策略及对应测试。

## 7. 第一版实施计划

1. 建立统一的时间语境计算结果，包含当前时间、上一轮时间、间隔时长、是否跨日和场景关系。
2. 给即时状态建立“发生时间、明确或预计结束时间、当前有效性、来源消息”语义。
3. 明确时长由程序计算；没有明确时长的即时状态按类别使用保守预计期限。
4. 回复前生成简短的时间结论，供所有卡片共同使用。
5. 旧事件继续保留，但过期后不得作为当前事实。
6. 用跨小时、跨日、跨午夜、明确恢复旧话题和不恢复旧话题覆盖自动测试。

第一版不要求建立通用自然语言时间知识库，也不要求识别所有复杂日期表达；无法可靠解析时保留原始时间并降级为不确定历史事实。

## 8. 第一版锁定参数

- 场景重新判断边界：间隔大于或等于两小时；
- 无明确时长的即时状态：达到两小时边界后降级为历史，不删除；
- 跨本地日期：默认新即时场景并关闭旧即时状态；
- 无日期且所述钟点已经过去：标记为不确定，不自动解释为次日；
- 第一版不新增临时状态持久化表，只在当前 4000-token 原文窗口内精确计算；
- 明确时长只解析时间表达，不用 Python 关键词表判断“困、吃饭、工作”等语义类别；
- 不新增第二次模型调用，时间候选修饰哪段语义由本轮主模型结合原文判断。
