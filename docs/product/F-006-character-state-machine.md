# F-006 · 角色状态机第一版

| 项目 | 内容 |
|---|---|
| 状态 | FSM v1 已实现 · Reviewer Round 4 PASS · 待负责人真机验收 |
| 适用范围 | 仅社交卡 |
| 前置依赖 | F-001 时间一致性、F-002 日常代理运行时 |

## 1. 产品目标

让社交角色的内部状态随真实时间、日常活动和用户互动有界地变化，并能在应用关闭后恢复；状态变化必须可解释、可追溯，不能由模型每轮随机覆盖。

## 2. 第一版范围

### 2.1 持久状态轴

- 精力：0–100；
- 情绪效价：-100～100，表示整体偏正面或负面；
- 情绪唤醒度：0–100，表示平静到活跃；
- 最后状态结算时间；
- 最近一次有效变化的来源。

### 2.2 瞬时情绪

瞬时情绪记录类型、原因、开始时间、预计减弱时间和强度。到期后只保留为历史事件，不继续作为当前状态。

### 2.3 派生表现

用户界面和提示词使用由状态轴派生的自然标签，例如兴奋、满足、平静、烦躁、失落或疲惫，不要求模型看到或复述原始分数。

### 2.4 暂不处理亲密度

- 现有亲密度继续保留兼容读取，但第一版不新增评分规则；
- 每日无条件衰减和按聊天轮次加减分的问题记录为后续改造项；
- 第一版 FSM 不依赖亲密度决定状态转移；
- 新状态事件不得顺便修改亲密度。

## 3. 状态输入

- F-001 提供经过时间、跨日和状态有效性；
- F-002 提供睡眠、休息、专注、娱乐、通勤等活动及其持续时间；
- 用户互动只先被归类为有限事件，例如被支持、被称赞、发生冲突、收到道歉、共同兴趣或中性互动；
- 外部天气只能产生很弱的可选影响，不得支配情绪。

## 4. 转移规则

- 状态更新由单一状态结算服务执行，其他模块提交事件，不直接覆盖最终数值；
- 模型可以建议事件类型和强度，但不能直接指定精力或情绪分数；
- 精力按活动和经过时间结算，睡眠恢复、专注和通勤消耗、休息适度恢复；
- 情绪随事件有限变化，并随时间缓慢回到角色设定定义的基线；
- 单次事件有最大影响幅度，重复同类事件收益递减；
- 派生标签使用迟滞区间，防止数值在边界附近导致心情来回跳动；
- 应用关闭期间不运行高频后台模型，下次启动或发生事件时按时间差补算。

## 5. 角色设定的作用

角色设定提供基础精力、情绪基线、恢复速度和对不同事件的敏感度。它不保存当前数值，也不能被状态机自动重写。

当前验收版只做最小联动：CharacterState 的自然状态可以影响角色当下的表达。Persona 可以记录休息时间里符合角色的调节方式，但当前不据此自动选择活动。状态本身不直接重写当日日程，也不因为一次情绪变化触发 DailyAgent 重排。V2 若需要让 FSM 在休息时决定实际活动，应另加可替换的行为选择层，不扩充或改写状态轴；总计划见 `docs/design/character-mechanism.md`。

## 6. 现有契约修复

当前新版提示词、标签解析器与数据库对 mood、intimacy 字段的名称和取值范围不一致。第一版实施前必须先统一状态标签契约，并添加“提示词输出能够被真实解析和写入”的契约测试。

第一版新契约应优先表达“发生了什么事件”，不再让模型直接提交最终状态分数。

## 7. 明确不做

- 亲密度重算；
- 欲望、自主目标和复杂心理模型；
- 每 30–60 分钟一次的后台模型心跳；
- 偏好成长与角色设定自动改写；
- 长期反思和持续生活线；
- 助手卡的虚构情绪状态机。

## 8. 验收标准

- 睡眠、休息、专注和通勤对精力产生方向正确且有界的变化；
- 昨晚的瞬时烦躁或困倦在第二天正确过期；
- 同一事件重复提交不会重复结算；
- 应用关闭后补算与持续运行得到等价结果；
- 用户表达难过不会被直接复制成角色自己的难过；
- 模型输出非法事件或强度时安全忽略，不阻塞聊天；
- 多个来源提交事件时由同一服务串行结算，不发生最后写入者任意覆盖；
- 提示词只看到自然状态结论和必要原因，不机械展示原始分数；
- 第一版不会改变亲密度。

## 9. 仍需锁定的参数

1. 各活动每小时的精力变化范围；
2. 情绪回归基线的速度；
3. 单次互动事件的最大影响；
4. 瞬时情绪的默认持续时间；
5. 派生情绪标签的阈值与迟滞区间。
