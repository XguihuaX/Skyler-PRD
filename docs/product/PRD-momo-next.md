## 0. 文档用途与状态

Skyler 是 MomoOS-v2 重构后的产品名，先供用户自己长期使用，按商业产品质量建设。本文供用户、两台设备上的 Codex 及后续实现者共同使用。当前工作的目标是把已确认的体验交给实现和验收；不重新进行一级需求访谈。

| 状态 | 本项目如何使用 |
| --- | --- |
| 已确认 | 用户已确定的体验、范围或采用方向，后续设计据此推进 |
| 方案/建议 | 已有依据的实施选择，尚未等同用户指定的产品规则 |
| 待验证 | 有候选或已有实现，但没有目标设备的通过记录 |
| 独立专项/后置 | 保留的测试或后续功能，按 §2.2 各自安排 |

现行需求由本文与[功能行为明细](SPEC-momo-next-details.md)共同组成。主文定义范围、规则、待决和顺序；明细保留已谈过的具体行为与样例。技术候选见[复用总表](SKYLER-FUNCTION-REUSE.md)。用户原话与历次改变保留在[决定日志](.memlog.md)、[交接历史](HISTORY-requirements-handoff-20261122.md)及[重整前 PRD](HISTORY-momo-prd-v0.94.md)。

## 1. 产品目标与使用场景

Skyler 是能自然交流、理解和记住相关经历，并在用户授权下协助完成日常事务的个人 AI 助手。一个角色贯穿聊天、办事与跟进，主要交互通过 Skyler 自身客户端，QQ 不作为当前主线。

| 使用主线 | 用户希望获得的结果 | 已有场景 |
| --- | --- | --- |
| 交流与陪伴 | 接得住上下文和更正，有稳定风格，参与分寸合适 | 聊上海行程；游戏时想安静；第二天聊共同看过的翻盘 |
| 事务处理 | 从聊天委托得到可检查的结果，能接管和停止 | 整理报价、读资料、扫码后继续上传、按授权回邮件 |
| 持续跟进 | 跨时间记得并推进，按约定时机回报 | 定时/条件提醒、等最终报价、醒后汇总重要消息 |
| 出差使用 | 主机关机时 Mac 可接替，返程带回新记录 | 出差前主机交给 Mac，一周后交回主机 |

这些例子用于验收；上海、路牌、报价、Minecraft 等具体内容不构成固定台词、指定游戏或新增业务规则。[十一项回放案例](../../.agents/skills/momo-refactor-cases/references/cases.md)

术语：**主机**指用户的 RTX 5070 Ti 设备；**服务端**指当前运行麦麦及所需后台服务的设备，计划交接后可以是 Mac；**客户端**负责输入、播放和角色显示；**主人会话**指麦麦网页与官方桌宠共用的内部私聊；**旧 Momo**指重构前代码与资产。

| ID / 功能域 | 已确认体验与可检查结果 | 采用方向与明细 |
| --- | --- | --- |
| FR-01 对话与理解 | 日常聊天、理解指代与补充、更正、区分讨论和执行；能回看记录。用户更正后采用新的理解；后台办事时仍可聊天 | 沿用麦麦私聊和接话机制。主动程度、多段会话后定。[对话明细](SPEC-momo-next-details.md#511-n-01-对话与理解二级功能草案) |
| FR-02 语音交流 | 普通话夹少量英文；唤醒后连续交流，特定游戏/工作场景可免唤醒记录并主动陪伴；直接发言逐条留原声可回听。支持让话、打断、插问后明确“继续”接续，暂停 TTS 时仍可文字交流与收音 | ASR 选 faster-whisper medium / large-v3-turbo；接入自训 GPT-SoVITS 音色及声音库。全/半双工目标保留，默认模式待测；默认系统音频设备，需防自身回声。多人分人另测。[语音明细](SPEC-momo-next-details.md#54-n-06-语音能力扩展新增方向) |

| FR-05 信息、文件与个人资料库 | 读取、整理资料并交付可打开的成果；长期材料显式导入，追问出处时能回查来源。有可核对新版时提醒，用户暂缓就保留旧版、同意后再更新 | 采用麦麦知识与会话附件能力，办公/媒体按现成工具组合；生成和跨端交付分别验。自拍与短片候选见复用总表。[文件明细](SPEC-momo-next-details.md#资料与成果) |
| FR-06 任务与工作流 | 单次、条件、周期提醒及到点办事；按事件等待，达到约定结果只回报一次并结束跟进；后台任务可查状态、停指定任务、完成后回原会话。离线恢复遵循最新修改/取消，明确过期事项留记录、不推定用户已完成 | 单次/条件与普通后台任务先用麦麦，周期用 DSH Schedule，事件按来源接入。周期临时改一次、下周照旧须验；运行中追加要求后置。[任务明细](SPEC-momo-next-details.md#日程与持续跟进) |

| FR-09 人格与角色呈现 | 首期一个角色，稳定内核与可塑造方向；人格贯穿聊天和办事。保留窗口/仅角色、立绘馆及 Live2D；角色关联音色和 Prompt，状态对应真实收听、生成、播放或执行 | 麦麦完整人格机制优先；正式前端共同重设计，旧客户端与资产按需复用。Live2D 的发布批次与制作目标待研究。[人格](SPEC-momo-next-details.md#51-n-071-单角色人设首轮范围已定) · [呈现](SPEC-momo-next-details.md#55-n-07-立绘馆live2d-与前端重设计) |
| FR-10 设置与用户控制 | 集中组织角色、声音、模型/API、感知、扩展及权限管理；支持能力启停与模式/实现选择，角色 Prompt 随角色管理；能辨认配置和真实就绪状态，预留游戏插件入口 | 沿用宿主及插件已有管理和授权；统一账号状态页属于建议，正式布局后定。[设置明细](SPEC-momo-next-details.md#510-统一管理入口与角色-prompt-归属) |

## 3. 共同行为与质量要求

- **RULE-01 复用。** 优先使用现成配置、插件和接口，真实差异再适配；不把插件存在、源码覆盖或局部测试记为整条流程已验收。
- **RULE-02 授权。** 办事沿用 DSH 会话权限与单次确认；需确认的实际路径必须等待用户决定。邮件插件自身的可信收件人规则同时生效。下载和更新按 FR-08 处理。
- **RULE-03 数据与更正。** 直接对 Skyler 说的话默认保留逐条原声；聊天记忆可查看、更正、删除。感知原件和长期记忆的保存范围、历史与录音的期限及导出仍待定。计划、过时提醒及回放输入不能记成真实完成经历。
- **RULE-04 真实状态。** 结果有实际产物或外部状态可核对，失败不报成功；生成、播放、后台任务的停止分别处理，打断说话不自动取消无关任务。继承旧项目真实就绪、模型名、角色名与运行状态约束。
- **RULE-05 工程与资产。** 代码模块化、组件可替换，技术文档随实现交付。盘点旧资产后决定迁移，正式前端重新设计；不按代码年龄或行数直接删能力。
- **RULE-06 资源体验。** 分别观察 RAM、显存、响应/语音首声与打断延迟、Token/费用和稳定性。按需读取记忆与技能；性能门槛及出差模式的本地/远程模型组合以实测和用户体验确定。

## 5. 采用方向与设备分工

**已定方向：麦麦作为 Skyler 主程序，适用的 DSH 插件留在 DSH，按需委托。** 麦麦承接私聊、人格、记忆、历史与日程；旧 Momo 提供客户端、角色和声音资产候选。具体桥接方式和改动点见[架构说明](ARCH-001-runtime-renewal.md)，无需另建一套 Momo 主后端作为前提。

主机优先运行服务。Mac、手机从实际使用设备采集语音、画面并播放；电脑和游戏操作发生在目标设备。主机离线时按 FR-11 计划交给 Mac；两端均未运行服务时，实时回复与任务执行不可用。

网页与官方桌宠已有同一主人会话路径。手机可使用网页，Android 另有官方桌宠；微信有内置 ClawBot 私聊入口。微信适配器与内部主人会话身份不同，共享记忆和连续历史需分别验证。官方入口/平台覆盖、微信语音限制及 Mac 上游实测范围属于版本证据，见[多端接入核对](SKYLER-CHANNELS-AND-HANDOFF.md)。

当前已定位的具体差异：Tobs 默认会话归属与原声释放；某条麦麦 ACP 回调自动允许一次；所查语音候选的逐句待机和硬打断续播差异。只有实际选用相关路径，才据此确定适配工作。[差异与条件](SKYLER-FUNCTION-REUSE.md#哪些情况实际需要改代码)

## 6. 验收与成功条件

成功以用户可见结果判断：能继续聊、记忆更正真正生效、提醒按正确条件出现、任务交付可打开且内容正确、语音能听清并打断、交接后新增数据仍在。具体步骤采用[设备验收清单](SKYLER-5070TI-ACCEPTANCE.md)与案例册。

开发侧完成可自动回放的功能验证，保留输入、版本、实际结果和证据；用户在自己的设备上评议自然感、音色、内存/响应和实际游戏体验。局部函数、录制样本、模拟向量、测试服与真实设备结果分别记录，不相互替代。

评价同时观察：功能成功与错误/重复操作；自然交流与不必要打扰；识别/生成质量与延迟、资源、费用。阈值尚未确定的保持 OQ-03，不虚填通过线。涉及失败、停止、恢复的场景按已确认行为回归；需要用户取舍的未知默认值回到相应 OQ。

## 7. 后续任务

[执行任务清单](SKYLER-TASKS.md)是接手后的操作入口，顺序为：原版主机与 Mac 聊天 → 原生记忆/日程与计划交接 → DSH 委托 → 基础语音及多端感知 → 文件、跟进、网页、游戏 → 正式界面与增量优化。独立专项按 §2.2 保留，顺序不缩减首轮范围。

每项先交付一次可复现结果，发现差异再形成小批改动并回归。两端以相同文档/代码版本交接，主机 Codex 管主机服务与 GPU，Mac Codex 管客户端和 Mac 本地服务；真实数据交接与 Git 文档/代码同步分别处理。

最近可开始的是任务 T-01：用户尚未安装麦麦，由主机 Codex 检查环境、从官方下载安装、初始化并配置聊天模型；随后主机网页完成真实私聊和重启回看，Mac 准备客户端并连接同一个 Bot 接着聊。当前未记录该任务已经通过。
