# T-01 · 发给 5070 Ti 主机 Codex 的接手提示词

2026-11-22 · 对应 PRD v0.96。复制以下正文发送给主机 Codex。此文件是执行输入，尚不是验收结果。

---

请从私有仓库 https://github.com/XguihuaX/Skyler-PRD 接手 Skyler 的 T-01：检查这台 5070 Ti 主机的麦麦环境，先跑通主机原版聊天，再与 Mac 联测同一个 Bot、同一段主人聊天历史。请直接开展检查和验证。

**1. 取得需求。** 本机已有仓库时，检查本地改动后安全更新；没有则使用已登录的 GitHub 身份克隆到合适的项目目录。记录实际目录和提交号。先读 AGENTS.md、README.md，以及 docs/product/ 下的 PRD-momo-next.md、SKYLER-TASKS.md、SKYLER-5070TI-ACCEPTANCE.md、SKYLER-VALIDATION-LOG.md；按需查架构和 SKILLS.md。本轮执行 T-01 与设备清单第 1、2 项，不重启需求访谈。这个仓库是需求与技能材料，麦麦程序在它自己的目录运行。

**2. 检查实际环境。** 先确认操作系统和 shell，再选命令。查已有麦麦目录、版本/提交、工作区和数据目录、启动方式、依赖环境、进程、日志、WebUI 监听地址/端口、当前 Bot，以及回复所需模型的配置和运行位置。检查显卡/驱动可用情况，但使用远程文字模型时可先完成聊天。先从本机获取答案，只问确实查不到且阻塞下一步的信息。报告模型名称和配置是否可用，不输出密钥或凭据。

**3. 跑通主机基线。** 沿用已安装版本和配置，按该版本文档补必要依赖、处理实际启动问题或做最小配置修复，记录改动，不自动升级整个麦麦。通过主机 WebUI 的主人私聊发送唯一记号 T01-HOST-日期时间-随机串，取得真实模型回复并记录时间。确认服务没有执行中的任务后正常停止/启动，再回同一 Bot、同一私聊确认原消息和回复还在。页面能打开不等于聊天通过。若未找到程序、缺模型配置或需要本人登录，明确具体缺项，继续不受影响的检查。需要代码修复时先记录复现和拟改动。

**4. 准备 Mac 接入。** 按实装版本配置官方桌宠远端入口；已查 v1.4.8 使用 desktop_pet.enabled=true、desktop_pet.mode=remote，其他版本以实际配置为准。核对监听地址、网络路径和端口，优先使用已有局域网或私人网络；给 Mac 的地址不能是主机的 127.0.0.1，保留现有登录与访问控制。

返回一段可直接转给 Mac Codex 的联测信息：主机可达地址/端口、Bot 名称和可识别 ID、麦麦版本、需求提交号、主机测试记号与时间、客户端选择和具体操作。凭据由我在对应界面输入，不放进消息或 Git。

**5. 两端联测。** Mac 先确认主机网页可达，再通过官方桌宠登录同一个 Bot，看到主机记号后发送 T01-MAC-日期时间-随机串并取得回复。主机网页应能看到 Mac 消息与回复；Mac 关闭并重开客户端后，两组记录仍可回看。你核对主机接收、会话归属和持久化，Mac Codex 或我确认 Mac 界面实际表现。双方使用同一个需求提交。

需要 Mac 配合时交付明确操作并等待真实回报；尚未联测时写“主机侧完成，等待 Mac 联测”。若 Mac 网页可用而桌宠失败，分开记录，按实际错误检查网络、登录、Bot 选择、客户端版本或是否已有桌宠占用，不替 Mac 写通过。

**6. 留下交付。** 在 docs/product/SKYLER-VALIDATION-LOG.md 追加 T-01 实际记录：设备/系统、程序目录与版本、需求提交、必要配置、输入与步骤、预期、实际、证据位置、结论和下一步。记录可复现的故障与解决办法；私人聊天、凭据和原始日志留在本机。

最终分开说明主机和 Mac 已完成什么、剩余具体问题，以及是否达到“真实回复、同一段历史、重启/重开后可回看”。全部通过后更新任务状态并建议进入 T-02。本轮先验证原版，不展开 DSH、语音、摄像头、正式界面或双机服务迁移。验收记录先保存在主机本地，交付文件路径与摘要；提交和推送测试记录另按我的后续指令执行。
