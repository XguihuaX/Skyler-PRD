# F-003 · 持续生活线

| 项目 | 内容 |
|---|---|
| 状态 | 待验收 · Reviewer Round 1 repair 后 PASS |
| 适用范围 | 仅社交卡 |
| 优先级 | 中高 |
| 前置依赖 | F-002 日常代理运行时、F-006 角色状态机第一版 |
| 后续依赖 | F-004 分享储备、F-005 偏好成长 |

## 1. 产品目标

让角色的阅读、追剧和个人创作能够跨天连续推进，而不是 DailyAgent 每天随机生成一段互不相关的生活。

角色需要知道：自己正在进行什么、上次进行到哪里、今天是否想继续、实际推进了多少，以及为何暂停、放弃或完成。

第一版重点不是让角色无限自主寻找内容，而是建立可信、可解释、可补算的持续项目系统。

## 2. 核心原则

### 2.1 推荐创造机会，不创造义务

用户推荐一本书或一部剧，只会创建候选，不会直接变成角色必须执行的任务。

角色可以：

- 感兴趣并计划试读或试看；
- 先记下，等当前项目结束后再考虑；
- 因题材、时间或当前负担暂时搁置；
- 明确拒绝；
- 尝试后继续、暂停或放弃。

不得使用“亲密度高所以必须接受推荐”之类的服从规则。

### 2.2 角色具有有限主体性

选择是否开始或继续一个项目时，需要同时参考：

- 角色长期兴趣与明确雷区；
- 用户推荐，但只作为有限加权；
- 当前已经进行的项目数量；
- 距上次推进时间；
- 当天真实空闲时段；
- F-006 提供的精力与状态；
- 最近是否重复安排同类活动；
- 临时事件或更高优先级活动。

角色不能因为 LLM 一次随机输出就永久开始、完成或放弃一个项目。

### 2.3 计划不等于完成

日程中写了“看书”或“看剧”，不代表进度已经推进。

只有满足以下条件，系统才可以结算进度：

1. 日程块引用了明确的生活线 ID；
2. 对应活动时间真实经过；
3. 该时段没有被临时覆盖或中断；
4. 同一时段尚未结算；
5. 项目仍处于可推进状态。

### 2.4 结构化进度与主观感受分离

程序负责确定性事实：

- 阅读页数、章节区间；
- 已完成集数；
- 创作阶段和有限完成度；
- 有效投入时长；
- 是否达到完成边界。

模型可以在一次真实体验结算后生成有限感受，但不能直接修改结构化进度。

## 3. 第一版支持的项目类型

### 3.1 阅读

至少记录：

- 作品名与作者（已知时）；
- 当前页、章节或阅读区间；
- 总页数或总章节（可选）；
- 估算阅读速度；
- 上次有效阅读时间；
- 当前状态。

无可靠页数时优先使用章节或“开始／前段／中段／后段”等粗粒度区间，不能伪造精确页码。

### 3.2 影视与动漫

至少记录：

- 作品名；
- 当前已完成集数；
- 下一集；
- 总集数（可选）；
- 单集时长或分集时长（已知时）；
- 上次有效观看时间；
- 当前状态。

不足一集的剩余时间可以记录为本集观看分钟数，但不得自动宣称该集已经看完。

### 3.3 创作项目

第一版支持绘画、写作和手工类个人项目，至少记录：

- 项目名；
- 创作类型；
- 当前阶段；
- 有限完成度；
- 下一步；
- 上次有效推进时间；
- 当前状态。

完成度必须由阶段规则和真实投入时间共同限制，不能让模型每次任意增加百分比。

游戏、健身、旅行、课程和植物照料不进入第一版，后续依据真实需求扩展。

## 4. 生命周期

第一版状态：

```text
候选
  → 待考虑
  → 计划尝试
  → 试读／试看／试做
  → 进行中
  → 暂停
  → 完成
  → 放弃
  → 已拒绝
```

规则：

- `候选／待考虑` 不占用正式进行中名额；
- `计划尝试` 只有进入真实日程后才转为试用状态；
- `暂停` 保留进度，但不自动进入日程；
- `完成／放弃／已拒绝` 不再自动推进；
- 放弃必须基于真实尝试或明确角色决策，不能在尚未体验时编造负面体验；
- 用户可以再次推荐已拒绝项目，但系统应保留历史决定，不得当作首次推荐。

## 5. 项目来源

第一版允许：

1. 角色卡预设候选；
2. 用户在对话中明确推荐；
3. 用户或前端手动创建；
4. 已存在项目完成后，由 DailyAgent 从已确认候选池中选择下一个。

第一版不允许角色未经约束地联网搜索并永久开始新作品。

后续可增加真实内容发现：搜索只负责返回带来源的候选，角色仍需经过“待考虑 → 计划尝试”流程，不能把搜索第一项直接认定为自己的选择。

## 6. 每日选择与继续规则

选择发生在每日计划生成或明确重排时，不运行高频 LLM 心跳。

程序先进行确定性筛选：

- 项目状态允许推进；
- 未超过同时进行数量；
- 存在匹配的空闲时段；
- 时段长度满足最小推进单位；
- 当前精力适合该活动；
- 没有临时覆盖或更高优先级事件；
- 没有触发连续重复惩罚。

筛选后可以向每日规划器提供少量候选及解释字段。规划器只能选择候选、安排时段或选择今天不推进，不能自行创建未登记项目、修改进度或宣布完成。

第一版并发限制建议：

- 正式进行中的书最多 2 本；
- 正式追看的影视／动漫最多 2 部；
- 主要创作项目最多 1 个；
- 同一项目不要求每天推进；
- 连续安排多日后允许自然留空。

## 7. 进度结算

### 7.1 阅读

依据有效阅读时间和项目估算速度计算有限页数或章节区间。最终对话表达可以模糊化为“看到四十多页”或“刚读完第二章”，底层仍保存结构化进度。

### 7.2 影视与动漫

依据有效观看分钟数和单集时长结算。只有累计达到完整单集时长才增加已完成集数；剩余分钟进入下一集的部分进度。

### 7.3 创作

依据项目阶段、有效投入时间和阶段上限推进。单次结算不能跨越多个需要主观确认的重要阶段。

### 7.4 幂等与补算

- 每个推进区间使用稳定结算 ID；
- 同一日程区间重复恢复或重启不得重复加进度；
- 应用关闭期间只补算已经存在且可验证的日程区间；
- 缺计划、项目引用不明或活动被覆盖时不推进；
- 不从 `current_activity` 自由文本猜测项目进度。

## 8. 真实性与内容边界

- 现实作品的作者、集数、时长、章节和更新状态必须有可靠来源；
- 只有作品名和观看时长时，可以说“继续看了两集”，不能编造具体剧情；
- 具体剧情评价必须来自已获取的分集摘要、合法内容信息或用户提供的内容；
- 无可靠内容时只允许生成一般体验，例如“看得挺投入”，不得声称某个不存在的反转或角色死亡；
- 虚构创作项目必须明确是角色自己的虚构作品，不能冒充现实新作；
- 剧透等级作为项目字段保存，回复时交由 F-007 上下文仲裁执行。

## 9. 体验记录

一次有效推进可以产生一条有限体验记录：

- 推进前后结构化进度；
- 有效投入时长；
- 当时精力与环境；
- 简短主观感受（可选）；
- 是否想继续；
- 暂停或放弃原因（存在真实体验时）；
- 是否形成分享候选；
- 来源与发生时间。

体验记录不是永久偏好。是否改变偏好属于 F-005；是否主动分享属于 F-004。

## 10. 与其他功能的关系

### F-002 DailyAgent

- 负责把生活线安排进真实日程；
- 提供实际经过、被覆盖和跨午夜的活动区间；
- 不直接修改项目进度。

### F-006 状态机

- 提供精力和内部状态供每日筛选；
- 可以受阅读、娱乐或创作活动影响；
- 不直接决定作品进度或永久偏好。

### F-004 分享储备

- 消费 F-003 产生的“值得分享”体验；
- 决定何时、以什么方式分享；
- 不反向伪造 F-003 体验。

### F-005 偏好成长

- 消费多次真实体验；
- 决定是否形成或改变偏好；
- 单次推荐、单次尝试或单次感想不得直接改写 persona。

### F-007 上下文仲裁

- 决定当前对话是否适合提及生活线；
- 控制剧透、重复提及和回复自然度；
- 不修改项目真源。

## 11. 第一版不做

- 角色无限自主联网寻找新作品；
- 获取或保存完整书籍、剧集或视频内容；
- 高频后台 LLM 心跳；
- 自动生成精确剧情评价；
- 游戏、健身、课程、旅行等额外项目类型；
- 根据单次体验永久改变角色设定；
- 直接主动分享给用户；
- 把用户推荐当成必须服从的任务。

## 12. 验收标准

1. 用户推荐作品后，角色可以接受、观望、拒绝或稍后尝试，不会被强制开始。
2. 昨天看完第 4 集，下一次真实观看应从第 5 集开始。
3. 只观看 10 分钟时，不会宣称看完一整集。
4. 阅读、影视和创作分别使用合理的进度单位。
5. 被临时事件覆盖的时段不会推进。
6. 应用重启和重复结算不会重复增加进度。
7. 暂停、完成、放弃和已拒绝项目不会被自动排入日程。
8. DailyAgent 可以选择今天不推进任何生活线。
9. 同时进行项目数量受到限制，不会每天随机开启新作品。
10. 未获得具体内容信息时不编造剧情、章节或现实更新。
11. 单次体验不会直接改写角色永久偏好。
12. F-004/F-005 未启用时，体验可以保存，但不会自动分享或修改偏好。

## 13. 已锁定的产品决策

- 用户推荐仅进入候选池，不形成义务；
- 角色拥有接受、观望、拒绝、暂停和放弃的权利；
- 第一版支持阅读、影视／动漫和创作项目；
- 每日计划生成时决定是否继续，不使用高频心跳；
- 进度只由真实有效活动区间推进；
- 程序管理结构化进度，模型只生成受约束的选择与体验；
- 角色卡预设、用户推荐和手动创建是第一版项目来源；
- 自主联网发现、主动分享和偏好成长属于后续功能。

## 14. 第一版实施决策（2026-07-11 已锁定）

- 使用两张专用表：生活线项目真源与统一事件／结算账本；迁移必须幂等；
- 明确推荐通过 capability 创建候选，REST 提供手动创建与受控状态转换；普通讨论不进入候选；
- 推荐 capability 只能创建候选，不能接受、推进、完成或改写 Persona；
- 第一版不联网查作品元数据；缺少可靠页数、章节、单集时长或阶段配置时，只累计可验证时长并保守降级；
- 每日候选采用确定性零随机排序；已开始项目优先，近期重复只软降级，允许今天不推进；
- 并发上限固定为阅读 2、影视 2、主要创作 1；
- 生活线日程块使用白名单 `life_thread_id`，`slot_id` 由程序稳定生成；
- 创作阶段到达 100% 后必须走显式、幂等的阶段确认；一次只确认一个阶段，最终阶段确认后才完成；
- 角色卡预设通过显式结构化 preset 列表摄取，不解析 `lore`；删除预设不删除已有历史，已开始项目不被预设修改覆盖；
- 第一版完成后端、REST 与聊天工具链；前端列表和编辑交互后续单独设计。
