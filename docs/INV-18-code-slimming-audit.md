## 第一刀建议

先抽离 `main.py` 内的**迁移编排**，把完整顺序与 TTS cache 依赖集中到一个数据库启动模块，`lifespan` 只调用该模块并保留原 boot mark。该切口不改变用户交互、模型提示或语音链路，适合作为回归基线。具体实施前需把当前迁移调用顺序记录为清单；实施后比对清单、运行编译检查与启动相关测试。只移动职责不算最终瘦身，第二步再审查可合并或退役的旧迁移/兼容路径，并以真实数据库升级测试证明安全。

后续优先审查 `chat.py` 的上下文装配和工具暴露，再审查 WebSocket 的轮次状态。每个切口都以「一份可读 diff、一个明确行为不变量、一组相关回归」交付。当前已有的测试失败和前端 `tsc -b` 错误应作为基线单列，不归因于瘦身修改。
