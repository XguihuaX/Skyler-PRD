# Skyler 角色系统总设计与演进计划

> 状态：总设计真源，持续更新。本文描述 Persona、CharacterState、FSM、DailyAgent、life thread、memory、世界约束与上下文仲裁如何协作，以及各版本明确做什么、不做什么。
>
> 文档分工：本文件负责整体架构与演进顺序；`docs/product/F-001`～`F-008` 负责单项产品契约；`ROADMAP.md` 负责实际实施顺序与状态；具体角色事实记录在各自 character bible 中。

## 1. 总目标

给社交角色一个持久、有结构、可验证的生活与自我，使模型每轮读取已有事实和状态，而不是重新发明角色。

角色系统不是一个巨大 Prompt，也不是让一个 LLM 同时承担全部职责。它由稳定设定、动态状态、持续事项、当日计划、实际行为、外部约束和成长证据共同组成。

```text
Persona 稳定设定
  + WorldAnchor / 天气 / 现实资源
  + CharacterState 动态状态
  + life thread 持续事项
  + DailyAgent 当日计划
  + FSM 当前实际行为
  + memory 成长证据
  → Context Arbitration
  → Chat / Proactive / TTS / Motion 等输出
```

## 2. 各层职责与真源

### 2.1 Persona：她是谁

保存相对稳定、由创建者确认的角色事实和倾向：

- 身份、性格核心、价值倾向、说话方式与关系边界；
- 职业能力、生活阶段、长期作息倾向、兴趣和资源事实；
- 情绪表达与应对方式的候选范围；
- 知识迷雾、允许推断、需要确认和禁止推断的边界。

Persona 不保存今天的心情、当前精力、今天正在做什么、旅行是否已经发生或某本书读到哪里。

### 2.2 CharacterState：她现在如何

保存当前动态状态。第一版已有精力、情绪效价、唤醒度、瞬时情绪、自然状态标签和结算时间。

Persona 可以记录角色稳定的表达与调节倾向；CharacterState 只保存当前值和变化来源。二者不能互相覆盖。

### 2.3 life thread：什么事情还在继续

保存跨天持续的阅读、观看、创作及后续扩展事项，包括状态、进度和可验证事件。旅行、具体朋友关系或特殊长期事项进入系统前，也应先有结构化真源，不能从一句 Persona 倾向直接生成。

### 2.4 DailyAgent：今天大概怎么过

根据 Persona 的生活投影、世界锚点、真实约束和已登记持续事项，生成当天的基础计划。计划允许空档和伴随活动，不等于事情已经真实发生。

### 2.5 FSM：现在实际发生什么

结算经过时间和已验证活动，维护当前状态。当前第一版负责状态演化和当前活动读回；未来若要在弹性休息时段决定实际行为，应通过可替换的行为选择层扩展，而不是把所有行为规则塞进状态轴。

### 2.6 memory：角色怎样逐渐成长

保存有来源的经历和偏好证据。memory 可以支持偏好演化，但不能凭单次对话改写不可变身份，也不能把用户经历变成角色亲历。

### 2.7 WorldAnchor 与现实约束：什么事情可能发生

提供角色所在地、时区、私人场景、天气、交通和已确认资源。它们约束日程与行为，不负责决定角色性格。

### 2.8 Context Arbitration：这一轮应该怎样回应

决定用户本轮输入、角色状态、当前活动、Persona、屏幕/AX 感知和工具结果之间的优先级。它负责选取相关上下文，不创造新的角色事实。

## 3. Prompt 与数据装配原则

1. 平台规则、Persona、动态状态和本轮上下文分层装配，不互相复制。
2. 每个调用方只读取所需投影：ChatAgent 不需要完整生活档案，DailyAgent 不需要 voice samples，TTS 不决定角色事实。
3. 稳定前缀用于缓存；时间、状态和本轮证据进入短动态段。
4. 条件模块按需加载。普通日不注入旅行、生日、展览或其他特殊事件规则。
5. Persona 中的倾向不能直接证明事件已经发生；专名、车辆、宠物、朋友和经历必须有明确真源。
6. 单 Agent 与未来多 Agent 共用相同的事实优先级和 Persona 真源，不为每个 Agent 复制一份互相漂移的人设。

## 4. 当前验证版：芙芙基础 Persona

当前版本以芙芙作为第一张完整社交卡原型，目标是先验证稳定人物锚点能否让聊天和 DailyAgent 摆脱通用模板。

本版本包括：

- 完成芙芙的身份、性格、职业、居住、生活节奏、兴趣、饮食、资源和推断边界；
- 把人物设定投影为 Chat 和 DailyAgent 各自需要的最小上下文；
- 使用现有 FSM 的自然状态标签影响当下表达；
- 保持 Persona、CharacterState、DailyAgent、life thread 和 memory 的分层。

本版本明确不升级：

- 不让 DailyAgent 根据 mood 自动重排日程；
- 不让 FSM 自动替角色选择具体休息活动；
- 不自动生成旅行、展览、聚会或朋友关系；
- 不新增独立压力轴、欲望模型或后台高频思考；
- 不新增动态 Agent，也不进入多 Agent 调度。

芙芙可以在 Persona 中记录“休息时可能如何调节自己”，但当前版本只把它当作稳定人物资料和表达参考，不把它实现为自动行为规则。

## 5. V2：状态参与生活，但保持有界

### 5.1 弹性休息行为选择层

在 DailyAgent 已经给出休息、娱乐或空档的前提下，根据 CharacterState 的自然标签、精力档位、Persona 调节倾向和现实条件，选择当下更合理的实际活动。

边界：

- 只处理弹性休息场景，不改写固定工作、睡眠、约定和已发生日程；
- 使用自然标签和档位，不把原始状态分数交给 LLM；
- Persona 提供候选范围，状态只改变权重，不形成“心情差必定看动漫”的固定映射；
- 行为选择层可独立替换，不能反向改写 Persona 或状态轴。

### 5.2 mood-aware DailyAgent

DailyAgent 后续可以弱参考生成时刻的自然状态，但只影响可选休息和娱乐安排。

升级要求：

- 当前 mood、精力必须来自 CharacterState，不从聊天文本猜测；
- 不因一次情绪变化自动重生成整天日程；
- 不覆盖明确的工作、生活线、约定和世界安全约束；
- Prompt 明确状态只代表当前时刻，不能假设全天不变；
- 验收应覆盖同一角色在不同状态下有变化、但不会机械重复同一种应对活动。

### 5.3 旅行与特殊事件场景模块

保留同一个 DailyAgent，通过按需场景模块处理旅行、展览、生日、约定、交付日等特殊情况，不新增独立 Agent。

Persona 中的旅行倾向只能产生候选意愿。只有目的地、时间等必要事实成为已确认的 life thread 或结构化事件后，才能加载旅行模块并进入日程。普通日不加载这些 Prompt。

### 5.4 真实天气与安全升级

在现有天气快照基础上补充适合安全决策的预警来源与降级规则。极端天气优先限制不可能或不安全的活动，但不能凭普通降雨自动改变角色心情。

## 6. V3：关系、知识与多调用方协作

### 6.1 关系实体与社交图

具体朋友、合作对象、关系强度、共同经历和当前联系状态独立建模。Persona 只保存角色的总体社交倾向；没有关系实体时，不生成姓名、聚会和共同往事。

### 6.2 更完整的知识迷雾与感知边界

区分角色一般知识、专业知识、亲历事实和当前可见信息。屏幕感知、AX 与工具结果必须经过权限和上下文仲裁，系统知道不等于角色已经看见。

### 6.3 多 Agent / 多调用方 Prompt

当产品确实需要多个运行角色时，采用共享真源、调用方投影和统一仲裁：

- Chat 读取身份、说话方式、关系与当前状态；
- DailyAgent 读取生活资料、现实约束和持续事项；
- 状态结算器读取事件和已验证活动，不读取完整对话 Persona；
- 专项规划器只在结构化事件确认后读取对应场景模块；
- 所有调用方通过统一优先级处理冲突，不各自维护一份角色事实。

是否拆分新 Agent 由可观测收益、调用成本和失败隔离决定，不能因为 Prompt 变长就默认拆分。

## 7. 版本升级门

进入下一版本前必须满足：

1. 当前版本的人物事实和动态状态没有互相污染；
2. 没有凭空生成车辆、宠物、作品、朋友、地点或经历；
3. 日程保持稀疏、自然，有空档且不把计划当成实际发生；
4. 状态变化可追溯，聊天只看到自然结论而不是原始分数；
5. 新模块有明确输入真源、失败降级和关闭方式；
6. 新增 Prompt 内容有调用方投影和 token 预算，不默认全量注入；
7. 自动测试通过后仍由负责人真机判断角色是否自然。

## 8. 当前决策记录

- 当前以芙芙验证完整社交卡 Persona，但架构不写死芙芙。
- 当前版本保留现有 FSM 基础能力，不增加 mood 驱动 DailyAgent。
- 芙芙的休息调节方式写入人物设定，自动行为选择留到 V2。
- 旅行与特殊事件采用 V2 按需场景模块，并要求结构化事件真源。
- 具体朋友关系与社交图后置，不在第一版 Persona 中虚构。
- 当前不增加新 Agent；未来多 Agent 仍共享同一 Persona 与事实优先级。
